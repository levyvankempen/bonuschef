## 5. State that cannot be rebuilt

- [ ] 5.1 **Stop `dagster-daemon`, `dagster-webserver` and `streamlit` before restoring, leaving only `postgres` up.** Every schedule and sensor carries `default_status=RUNNING` precisely so a fresh host needs no one to unpause it — which means the github sensor begins loading `github__products` within seconds of the first `compose up`. Restoring into that races the load: the first attempt here produced 1,259,047 rows against the laptop's 1,193,311, the surplus being a partial duplicate load, and the `CREATE TABLE` statements failed as "already exists" while the `COPY`s appended anyway. Drop the affected tables and restore again with `ON_ERROR_STOP=1`, which turns that silent mixing into a stop. Take a `pg_dump` on the laptop covering the irreplaceable tables — `ah__store_markdowns` (append-only, holds the intraday markdown curve, cannot be back-filled because AH publishes only the present), `public.recipes` and `public.recipe_ingredients` (typed by hand) — and restore it into the guest; verify the row counts match and `fct_store_clearance_history` rebuilds with its full snapshot history
